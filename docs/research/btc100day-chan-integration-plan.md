# BTC 100-Day 方法论与缠论结合方案

> 研究日期：2026-09-19（UTC）
> 
> 先前版本记录的是诊断与方案；2026-09-19 已按 P0 范围完成代码修复并部署。缠论部分仍只保留方案，未改入业务逻辑。

## 1. 当前 AI 分析错误的证据

### 已复现

用同一批 Binance BTCUSDT 日线数据，同时执行当前 `services/geminiService.ts` 的阶段计算和页面 `components/AnalysisPanel.tsx` 的展示计算，得到：

```text
asOf: 2026-09-19T09:11:27Z
price: 81447.99
AI:   stage=rest, probability=70, consecutiveDays=2, gain7d=5.99%, gain30d=3.97%
UI:   consecutiveAbove=2, change7d=5.40%, maxGain30d=12.70%
```

这条反馈回路已运行成功，且明确捕获了两个指标口径差异：

1. AI 的 7 日涨幅从 `candles.length - 7` 取基准，页面从 `candles.length - 8` 取基准，存在一个交易日偏移；AI 的 30 日基准也应按完整 30 个日线间隔重新定义，而不是直接使用 `candles.length - 30`。
2. AI 的 30 日涨幅是 close-to-close；页面标题却显示“近 30 天最大涨幅”，计算的是任意低点到后续高点的 max run-up。二者不是同一个指标，当前 prompt 却都叫 30d gain。

### 高概率的逻辑问题

- `consecutiveDays` 实际是“站上 EMA15 的回溯计数”，不是理论原始定义里的“从单边快速上涨起点开始的周期日数”。因此它既被当作趋势持续时间，又被当作百日周期天数，容易把“短期重回 EMA15”误判成周期进入确认/预警阶段。
- 源码使用 `probability` 这个名字，但只是按 `criteriaScore` 的固定加减公式生成，没有先验、似然、观测事件定义或历史校准；“贝叶斯概率”目前是提示词叙事，不是可审计的概率。
- `liveCandles` 用实时价格改写最后一根日线的收盘、最高、最低，但成交量仍来自最多一小时前的本地缓存；未闭合日线被当成已确认日线参与 EMA、回撤和周期判断，可能造成盘中状态跳变。
- 页面、AI 服务和部署入口存在重复实现：`worker.js` 是当前 Wrangler Worker 入口，`functions/api/insight.js` 是另一份旧的 Pages Function 实现；两者 prompt 不同，后续修复容易只改到未生效的文件。
- FAQ 仍描述“后续 3 天内至少 2 天恢复”，但当前实际代码已改为“浅度跌破且前后都站上才容错”的孤立日规则，文档与执行逻辑不一致。
- 当前 prompt 要求 AI 给“具体操作建议”，原先没有结构化的 `WAIT/INSUFFICIENT_DATA/INVALIDATE` 输出约束，容易把研究状态包装成交易结论；本轮已明确允许 `WAIT`，完整结构化输出仍属于后续工作。

### 已排除或暂未确认

- `npm run build`、TypeScript 检查和 `git diff --check` 均通过；不是编译错误。
- `https://btc100.day/api/insight` 的 GET 返回 405，非法 POST 返回 400，说明线上 Worker 路由存在并在做输入校验；没有在本轮发送有效请求去消耗外部模型额度。
- 当前 DeepSeek 模型名不是首要嫌疑：官方变更日志说明 `deepseek-v4-flash` 可通过原 Chat Completions 接口调用；本轮已显式关闭 thinking，并通过真实线上请求确认请求已到达供应商。当前账户返回 HTTP 402，根因是余额/额度不足，不是前端指标计算或 Worker 路由错误。

## 2. 方法论研究结论

### 原始 100 天方法应当如何理解

可查到的作者转述材料把方法描述为：当“单边快速上涨”的强度和持续时间达到一定程度，向前寻找早期最低起点，同时保证区间没有破坏“单边快速上涨”前提；在周期中段逐渐提高确认概率；周级别确认比日线噪声更重要；在周期末前一到两周才重点发布风险提醒；作者也明确承认，随着方法公开和 BTC 市场结构改变，效果可能衰减。

因此更稳妥的定义是：

> 100 天是一个带宽较宽的行为/情绪时间先验，用于风险窗口和仓位管理，不是精确的顶部倒计时，也不是单独的买入信号。

一篇对 2010—2021 BTC 价格事件的研究找到多个约 50—100 天的快速上涨事件，但同时指出峰值时间仍难以预测。这支持“50—100 天是可以研究的事件窗口”，不能直接推出“第 100 天必然见顶”。

仓库当前把 `0-30 / 30-70 / 70-100 / 100+` 做成硬阶段，并把固定分数命名为概率，超出了目前证据能支持的强度。

### 缠论中适合借用的部分

缠论原始材料中可操作化、且与现有方法互补的部分主要是“结构”，而不是把所有术语直接塞进 prompt：

1. **分型、笔、线段**：把 K 线噪声压缩成可追踪的摆动结构。
2. **走势中枢**：用至少三个连续次级别走势的重叠区，描述盘整/平衡区与突破后的回抽位置。
3. **多级别关系**：大级别定义背景，小级别负责确认和失效，不把 1 分钟级别的背驰直接解释成日线反转。
4. **背驰/力度衰减**：作为“上涨仍在延续但边际力度变弱”的风险证据，而不是单独的顶部预测器。
5. **第三类买卖点的结构思想**：突破中枢后回抽不重新进入中枢，可作为趋势确认候选；若重新回到中枢，则降级或失效。

缠论原文也强调：某级别背驰导致的是该级别走势结束，但后续可能是中枢扩展、更大级别盘整或更大级别反趋势；这正好说明它更适合作为“结构状态和风险升级器”，不应直接变成“看到背驰就清仓”的绝对规则。

### 不建议直接搬入的部分

- 不把“笔/线段/中枢/背驰”交给 LLM 视觉描述；它们必须先由确定性规则生成。
- 不同时采用多个流派的笔定义、分型合并规则和中枢级别规则；先固定一个版本，否则回测会随着参数和解释方式漂移。
- 不把“第三类买点”直接等价成盈利买点；它只表示结构条件满足，仍需考虑成交成本、滑点、资金费率、流动性与执行时点。
- 不把 100 天、EMA15、缠论和情绪指标全部加权成一个未经校准的总分；先做正交实验，确认每一层是否提供增量信息。

## 3. 推荐的组合架构

### 分层职责

| 层 | 作用 | 首选输出 |
|---|---|---|
| 100 天层 | 行为周期与风险窗口 | `cycleCandidate`, `cycleDayRange`, `windowStatus` |
| 周线/日线结构层 | 趋势、中枢、突破/回抽 | `structureState`, `center`, `breakout`, `reentry` |
| 动力层 | 量价持续性与力度衰减 | `impulseStrength`, `volumeState`, `divergenceCandidate` |
| 执行层 | 只有在结构确认后给风险边界 | `entryZone`, `invalidation`, `positionLimit` |
| AI 叙述层 | 解释证据、冲突和等待条件 | 严格 JSON 或固定字段，不生成原始指标 |

### 建议的状态机

```text
NO_SETUP
  -> CANDIDATE       结构从中枢/下跌段转为向上，且快速上涨条件初步满足
  -> CONFIRMING      周级别仍支持，日线突破后回抽不重新进入中枢
  -> RUNNING         结构延续，100 天窗口只作为风险年龄
  -> EXHAUSTION_RISK 进入后段窗口，或出现同级别力度衰减/背驰候选
  -> INVALIDATED     深度跌破、重新进入中枢、或关键结构被破坏
```

关键点：`cycleDay` 只从可审计的结构起点开始，不能用“当前连续站上 EMA15 天数”替代；100 天到期也只升级风险，不自动翻转方向。

### 第一版最小可行组合

先只做三个缠论结构字段，避免过拟合：

1. 日线：分型 → 笔/线段 → 最近有效中枢。
2. 周线：只判定背景方向和是否仍处于中枢上方，不做微观买卖点。
3. 日线：中枢上破后的回抽是否重新进入中枢；将其作为确认/失效条件。

背驰先只做“候选标签”，用价格摆动幅度与 MACD 柱面积/归一化动量做同级别比较，并要求结构完成后才确认；第一版不让它单独产生交易动作。

## 4. AI 分析修复方案与实施状态

### P0：先修数据真相（已实施的部分）

1. 页面和 AI 现在共用 `services/cycleAnalysis.ts` 的同一套指标计算；回归测试锁定两者逐字段一致。
2. 已分开 `change7d`、`change30d` 和 `maxGain30d`，并修复 7 日/30 日 elapsed-day 基准偏移。
3. 已对 AI 请求增加严格输入校验、供应商错误分类和不泄漏正文的日志；`functions/api/insight.js` 已改为复用生产 Worker，避免双实现漂移。
4. 仍待后续处理：只用已闭合日线计算 EMA/周期、统一成交量口径和显示数据新鲜度；本轮保留现有实时价格体验。

### P1：把“概率”改成可审计状态（部分开始实施）

1. Prompt 已将当前 `probability` 解释为启发式证据分数，不再声称它是校准概率；字段重命名和历史校准仍待后续版本。
2. 若要恢复概率，先定义目标事件，例如“未来 14 天未触发失效条件且收益超过成本”；用历史滚动样本估计先验、条件命中率和置信区间。
3. AI 只接收结构化证据，输出：阶段、支持证据、反证、失效条件、数据新鲜度、`WAIT/OBSERVE/CONFIRM/WARNING/INVALID` 状态。
4. 价格位、收益率、周期日、缠论节点全部由程序生成，AI 不得自行补数字。

### P2：再加入缠论

1. 先离线标注历史样本，固定唯一的分型/笔/线段/中枢规则。
2. 做三组对照：100 天基线、100 天 + EMA/量价、100 天 + 缠论结构。
3. 使用时间滚动的 walk-forward 验证，按 bull、range、bear、急跌/事件冲击分层；加入手续费、滑点、资金费率，并保留空仓/等待结果。
4. 只有当缠论字段在样本外提升校准后的决策质量，且没有显著增加延迟、信号密度或回撤，才进入线上 AI 上下文。

## 5. 下一轮实施前的验收标准

- 页面指标与 AI 输入逐字段一致，当前已由 4 个回归测试覆盖 7d/30d 口径和共享计算；未闭合日线边界测试待后续补齐。
- 给定同一 `snapshotId`，重复分析不会因缓存或模型随机性改变事实字段。
- 任何数据源失败、过期或跨日线不完整时，状态为 `INSUFFICIENT_DATA` 或 `WAIT`，不补零、不猜测。
- 100 天只影响风险窗口，不直接产生买卖结论。
- 缠论状态能够回放到具体 K 线区间、中枢上下沿、突破/回抽事件和失效价位。
- 报告区分研究结论、历史统计和执行建议；没有样本外证据时，不显示“准确率”“胜率”或未经校准的百分比。
